# AI news automation: foundation and safeguards

This phase follows the supplied specification without claiming that an AI model can make zero mistakes. The existing Pulse news card and mobile news feed remain unchanged. Approved candidates are published through the existing `PublicationRepository` and `/v1/publications?kind=news` API.

## Implemented now

- Admin-managed HTTPS RSS/Atom feeds **or news website pages**, enable/pause, polling interval, last fetch time, and error. A global pause stops ingestion without removing queued work.
- Independent TypeScript ingestion worker (`packages/ai-news-worker`) that polls enabled sources, enforces timeouts and size limits, rejects redirects and private addresses, respects robots.txt, and submits source-linked candidates. For a news page it inspects up to six same-origin article links per check; for a direct article URL it reads that article.
- Canonical URL de-duplication through a unique database constraint. Similar headlines from different sources are grouped into a story for a two-publication cap. No copyrighted publisher media or full article body is imported.
- Each candidate arrives with a source-linked draft and an original Pulse PNG illustration. The API can request a structured draft from Ollama Cloud, using a server-only API key. It never trains a model on this machine. If Cloud is unconfigured or unavailable, it uses the supplied source excerpt and labels it as such. Missing excerpts are not invented and need editing. No OpenAI service or key is required.
- When a feed entry has an HTTPS media enclosure, or an article page exposes HTTPS Open Graph image/video metadata, intake preselects that URL for the review draft and records its publisher provenance. It publishes only when an admin approves the candidate; that approval is also the media-rights checkpoint. Items without media metadata continue to use original Pulse artwork.
- Cloud drafting requests a source-grounded English summary of five or six connected sentences. When the supplied article excerpt does not contain enough detail, the model must remain shorter rather than inventing facts. The non-AI fallback preserves up to six source sentences.
- Similar reports from different configured sources, even across sections, share a story group and display each original article link in the review queue. This is retrieval and comparison of current source metadata, not model training or an assertion that multiple sources independently verified every claim.
- Admins can approve and publish a complete draft in one click, reject it, or edit copy/media first. Intake never auto-publishes.
- A database advisory lock and reservation make the two-publication cap atomic for candidates assigned to the same story group.
- New candidates use the existing news category vocabulary and appear in the existing mobile news feed after publication.

## Important limits

The model call is optional and is not an independent fact check. Source credibility still requires human review. Headline/excerpt similarity over the most recent 30 days can miss differently worded reports or group similar but distinct events; the two-card cap is guaranteed only **within a detected group**. The default artwork is generated by Pulse rather than copied from the publisher. Source photos and videos require an explicit licensed HTTPS URL and attribution entered by the admin. A source excerpt is not enough evidence to synthesize a detailed story; the admin must open the original source before publishing.

Before enabling any future auto-publish rule, implement and test claim-to-source evidence links, source comparison, content-version history, category risk policy, licensing checks, idempotent publishing transactions, and quality monitoring. Politics, health, breaking news, and disputed claims must remain human-reviewed.

## Run

1. Apply database migrations with `pnpm --filter @pulse/database db:migrate`.
2. Start the Pulse API and admin dashboard as usual.
3. Set the same `ADMIN_API_KEY` used by the API in the worker environment. Build with `pnpm --filter @pulse/ai-news-worker build`, then start `pnpm --filter @pulse/ai-news-worker start` as a separate long-running process. Use `start:once` for a single pass.
4. For Ollama Cloud, create an API key in your Ollama account, then set `PULSE_NEWS_AI_PROVIDER=ollama_cloud`, `OLLAMA_API_KEY=<key>`, and `PULSE_NEWS_MODEL=nemotron-3-nano:30b` in the API server environment. Restart the API. The dashboard reports **API key configured**, not a successful generation, until an article is ingested. Do not put the key in browser/mobile code or version control. A Cloud call requires internet access and may consume plan allowance. If the key is missing or Cloud fails, source excerpts become drafts and the admin still must review them. The local Ollama provider remains available with `PULSE_NEWS_AI_PROVIDER=local`, `PULSE_NEWS_LLM_URL=http://127.0.0.1:11434`, and `PULSE_NEWS_MODEL=pulse-news:v1`; this uses local inference memory but does not train a model. `PULSE_NEWS_AI_PROVIDER=off` disables model attempts.
5. In Admin → AI News Queue, add a source with an HTTPS RSS/Atom URL, news page URL, or direct article URL. Review the source and approve or reject each candidate.

For this local setup, an example source is NASA's official `https://www.nasa.gov/news-release/feed/`. JPL's feed has returned HTTP 403; changing its interval cannot fix publisher access, so keep it paused unless access is resolved. To add a source, enter its publisher name, an HTTPS feed, news page, or direct article URL, its optional website URL, category, and check interval (2–1440 minutes). New sources default to two-minute checks; admins can change the interval later under Managed sources. The interval controls checks for **new** articles, not how often the AI invents drafts. The worker processes at most six current items per poll, retries a source after a fetch error, and skips already-ingested URLs before requesting a Cloud draft. Website discovery is intentionally bounded, same-origin, and based on recognizable article URLs; it will not work on every publisher layout, paywall, or JavaScript-only page. `--once --force` performs a manual verification sync; ordinary worker runs honor the configured polling interval. The queue can contain both older source-excerpt drafts and newer Cloud drafts, each labeled accordingly. A configured API key is not proof of generation; the dashboard reports active Cloud drafting only after a Cloud-generated candidate exists. For non-English excerpts, the Cloud prompt requests an English headline and summary; if generation fails, the original-language excerpt remains visibly marked for admin review.

Global coverage requires adding multiple publisher sources across countries and topics, with permission for the intended reuse. The admin can import up to 100 source definitions at a time as `name | HTTPS feed or website URL | section | check minutes`, and can edit each source's section and interval afterward. The source section is used by the mobile news filters; `stocks` is separate from `business`. This does not mean crawling every news website or TV channel. Before onboarding a source, check its access and licensing terms, attribution requirements, reliability, and whether its excerpt or article text is sufficient for a grounded draft. A publicly reachable page does not grant permission to copy its text or media into Pulse. Bulk onboarding can consume substantial Cloud allowance as new items arrive.

The abstract Pulse image is deliberately used when no permitted publisher photo/video is supplied; it is not a failed network image. In the review queue, an admin can paste and preview a permitted HTTPS image or direct video file URL and record its licence/attribution before publishing. Direct `.mp4`, `.webm`, `.mov`, and `.m4v` URLs are marked as video for the app player; a YouTube page or news article URL is not a direct video file. Published articles can also have their section, media URL, and evidence/attribution note corrected from News Articles without re-publishing the story.

The worker must run independently of the admin browser. Keep its admin key in server-side environment variables only; never ship it to the mobile app.
